# 小说工作台基础设计

## 范围

目标是本地桌面小说产品。保留 OpenWork 上游树以复用、对比和同步；独立 `writing.html` 只挂载小说模块，使用上游 Button/Input/Textarea/Label 和样式 token，避免云端登录、组织策略和运营服务成为写作的启动依赖。现有 OpenWork 入口保留。

`LOCAL_FEATURES.novelWriting` 在上游入口默认关闭。打开独立入口即显式选择小说产品；它不属于 Den 的云端功能发布，不生成 Den API/Helm 合同。

## 状态机

阶段为 intent/timeline/events/scenes/draft/style。每阶段 pending → waiting → approved；修改阶段后，已有下游变成 stale，未生成下游仍为 pending，确认指针清空。stale 产物可查但不可直接确认，必须重新生成。程序检查前序确认，模型无权推进状态。

生成成功并保存后才展示新版本。每次生成记录完整阶段输入、用户反馈、模型、引擎会话 ID、参考片段及来源。请求失败、取消或超时不创建版本。每阶段独立 OpenCode 会话，只有已确认上游进入输入，不将全程聊天反复堆入模型上下文。

style 阶段是审稿报告，不自动改写正文。接受报告不意味着应用建议；要修改正文，返回 draft 阶段输入要求，再重新核对风格。定稿提取 draft 的最新已确认版本。

## 参考素材

临时素材只提供表达参考。本书正文在用户主动整理时进入索引；定稿本身不触发整理。当前分类为透明的关键词初分，不声称 AI 语义分类，允许手工修正。全文保持原样，分类是索引信息。

检索先按段落和关键词排序，再从本书正文、临时素材各取最多三个片段，单片段上限 700 字符。修改已整理章节后，在重新定稿之前排除旧索引，不把旧定稿当作当前事实。后续可替换检索器与分类器，不改变阶段确认机制。

## 文件与恢复

`project.json` 是权威状态，其他 Markdown 为派生产物。桌面只写用户授权目录和固定格式路径；逐层解析真实目录，拒绝指向外部的目录链接。文件先临时写入再 rename，manifest 最后提交。写入串行，保存失败留在原状态。

这不是跨文件数据库事务：中途失败可能留下尚未被 manifest 引用的派生稿，重新保存会修复。外部编辑合并、文件锁与项目多窗口并发控制尚未实现。浏览器缓存也不是磁盘备份。

## 引擎

默认演示模式只验证流程；真正的 agent 执行由本地 OpenCode 完成。HTTP adapter 使用 V1 会话接口；模型认证交给上游 OpenWork/OpenCode。应用级 Authorization 仅内存保存。停止请求会转发到对应 OpenCode 会话，生成有 240 秒上限。

导出的 novelist 角色允许读取和检索，禁止写入、shell、子任务及引擎提问；生成内容由应用保存，让写入权限和确认状态保持一致。未来如开放 agent 写入，需要先添加路径范围、版本和状态事务约束。

## 验证

单元/契约测试覆盖跳步拒绝、上游修改、过期确认、定稿、显式整理、混合来源、备份验证、导出、OpenCode 会话调用和失败分支。文件测试覆盖中文文本、manifest 更新、路径穿越与目录链接。

UI 验证路径：载入演示 → 生成意图 → 确认 → 生成时间线 → 输入修改要求 → 查看 v1/v2 → 确认后续直到定稿 → 主动整理 → 刷新恢复。真实模型质量、真实引擎端到端和 Windows 签名发布单独记录，不用演示结果替代。

## 后续开发顺序

1. 验证一套真实 OpenCode V1 + 中文写作模型，补上引擎启动/就绪检测。
2. 独立版本化故事事实、人物状态与伏笔，建立章节修改后的更新规则。
3. 根据使用样本改进分类、检索与风格核对，再评估向量检索。
4. 在稳定协议上补多项目管理、外部文件修改冲突、迁移与签名更新。
